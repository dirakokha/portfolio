# امیرمحمود خاکنه — وب‌سایت شخصی و رزومه

وب‌سایت شخصی و رزومهٔ **امیرمحمود خاکنه** (دانشجوی فناوری اطلاعات، رودهن — تهران).
سایت کاملاً **ایستا** ساخته می‌شود، محتوایش در **Git** ذخیره می‌شود و با پنل
مدیریت فارسی (`/admin`) بدون نوشتن کد ویرایش می‌شود.

- طراحی: فارسی‌محور، راست‌به‌چپ، با تایپوگرافی سفارشی و انیمیشن‌های کنترل‌شده.
- نسخهٔ چاپی رزومه: `/resume/`
- پنل مدیریت: `/admin/`
- هزینهٔ اجباری نگه‌داری: **صفر**.

**آدرس سایت (GitHub Pages):** <https://dirakokha.github.io/portfolio/>
در این نسخه فقط نمایش عمومی فعال است؛ برای ویرایش از پنل، میزبانی روی Cloudflare
Pages (یا انتشار `workers/oauth/`) لازم است — بخش ۵ و `docs/DEPLOY.md`.

## ۱) چرا این معماری؟

| نیاز | انتخاب | دلیل |
| --- | --- | --- |
| میزبان سایت | **Cloudflare Pages (Free)** | بدون کارت اعتباری، پهنای باند نامحدود برای فایل‌های ایستا، دامنهٔ رایگان `*.pages.dev`، پشتیبانی از مخزن خصوصی، ۵۰۰ build در ماه (بررسی‌شده در آبان ۱۴۰۴) |
| مدیریت محتوا | **Decap CMS** (متن‌باز، MIT) | محتوا را در همان مخزن Git کامیت می‌کند؛ بدون دیتابیس و بدون سرویس پولی |
| ورود به پنل | **GitHub OAuth** + پروکسی رایگان روی Cloudflare Pages Functions | کلید محرمانه فقط سمت سرور؛ ورود منحصراً برای مالک |
| ذخیره‌سازی محتوا | فایل‌های YAML در `content/` | قابل خواندن، قابل دیف‌گرفتن، قابل بازگردانی از تاریخ Git |
| تصویرها | `public/media/` | همهٔ فایل‌ها روی همان میزبان، بدون سرویس ذخیره‌سازی بیرونی |
| فونت‌ها | **استعداد (نمایشی) + وزیرمتن (متن)** — هر دو OFL | میزبانی محلی، بدون Google Fonts و بدون CDN |

هیچ سرویس پولی، دیتابیس ابری، فروشگاه CDN فونت، ردیاب یا API پرداختی در پروژه
وجود ندارد. تنها سرویس‌های بیرونی: **GitHub** (کد و محتوا) و **Cloudflare**
(میزبانی و پروکسی ورود) — هر دو با پلن رایگان و بدون الزام کارت اعتباری.

> **توجه:** محتوای عمومی سایت در **زمان build** به HTML ایستا تبدیل می‌شود.
> بنابراین اگر پنل مدیریت یا ورود GitHub موقتاً از کار بیفتد، سایت عمومی بدون
> هیچ اختلالی کار می‌کند. درخواست‌های پنل فقط از مسیر `/admin/` انجام می‌شوند.

## ۲) دسترسی از ایران — وضعیت صادقانه

این پروژه برای مخاطبان داخل ایران طراحی شده، اما **دسترسی از داخل ایران
آزمایش نشده است** (تست واقعی باید از یک اتصال اینترنتی در ایران انجام شود).
وضعیت فعلی:

- `pages.dev` معمولاً در ایران باز می‌شود، اما برخی شبکه‌های ایران در دوره‌هایی
  دسترسی به Cloudflare را محدود یا کند می‌کنند. این وضعیت ثابت نیست.
- `github.io` (مسیر جایگزین GitHub Pages) در ایران بی‌ثبات‌تر گزارش شده است.
- سایت هیچ منبع بیرونی (فونت، تصویر، اسکریپت، ردیاب) بارگذاری نمی‌کند؛ بنابراین
  اگر خود دامنه باز شود، صفحه کامل و بدون شکست نمایش داده می‌شود.

**چگونه خودتان تست کنید:** از یک گوشی با اینترنت موبایل یا Wi-Fi خانگی در ایران،
آدرس سایت را باز کنید و همین صفحه را در حالت ناشناس (بدون کش) بازخوانی کنید.
اسکرین‌شات یا گزارش زمان بارگذاری، مبنای تصمیم‌گیری برای انتخاب میزبان خواهد بود.
اگر دسترسی ناپایدار بود، مسیرهای جایگزین در `docs/DEPLOY.md` آمده است
(از جمله میزبانی روی GitHub Pages یا هر میزبان ایستای دیگر بدون تغییر کد).

## ۴) اجرای محلی

```bash
npm install
npm run dev            # http://localhost:4321
```

برای ویرایش محتوا در حالت محلی (بدون نیاز به GitHub):

```bash
npm run cms            # سرور محلی Decap روی پورت 8081
# در یک ترمینال دیگر:
CMS_LOCAL=1 npm run dev
# سپس http://localhost:4321/admin/  → ورود با «local backend»
```

ساخت خروجی نهایی و آزمون‌ها:

```bash
npm run build          # dist/
npm test               # ۱۹ آزمون محتوا و خروجی
```

متغیرهای محیطی (اختیاری، در `.env.example` توضیح داده شده‌اند):
`SITE_URL`، `BASE_PATH`، `CMS_REPO`، `CMS_BRANCH`، `OAUTH_BASE_URL`.

## ۵) انتشار

راهنمای گام‌به‌گام (شامل ساخت اپلیکیشن GitHub OAuth و تنظیم متغیرها) در
[`docs/DEPLOY.md`](docs/DEPLOY.md) آمده است. خلاصه:

1. پروژه را در Cloudflare Pages به مخزن GitHub وصل کنید (Build: `npm run build`، Output: `dist`).
2. در GitHub یک اپلیکیشن OAuth بسازید؛ Callback URL: `https://<آدرس-سایت>/api/callback`.
3. در Cloudflare سه متغیر محیطی تنظیم کنید: `GITHUB_CLIENT_ID`، `GITHUB_CLIENT_SECRET`،
   `ALLOWED_GITHUB_LOGIN=dirakokha`.
4. در Cloudflare متغیر `SITE_URL` را برابر آدرس نهایی بگذارید و دوباره build کنید.

پس از این مراحل، `/admin/` فقط با حساب GitHub مالک باز می‌شود.

## ۷.۵) طراحی و لایهٔ حرکت

ظاهر سایت یک «دفترچهٔ کار فنی» است: کاغذ گرم، قواعد مویی، ورودی‌های شماره‌دار
(۰۱ تا ۰۴)، تیترهای درشت و برچسب‌های مونواسپیس لاتین. بخش نخست و تماس تیره‌اند و
بدنهٔ صفحه کاغذی است؛ ریل شمارهٔ بخش‌ها در کنار صفحه می‌ماند.

- همهٔ استایل‌ها در `src/styles/notebook.css` هستند؛ فایلی جز آن برای صفحهٔ اصلی
  وجود ندارد. سبک چاپ رزومه جدا و در `src/styles/resume.css` است.
- **ورود بخش نخست:** کرئوگرافی کوتاه با تأخیر پله‌ای روی خطوط نام، نام لاتین،
  معرفی و دکمه‌ها؛ نام از پشت ماسک بالا می‌آید. کل زنجیره کمتر از یک ثانیه است.
- **اسکرول:** هر ورودی با `data-reveal` و تیترها با `data-mask` ظاهر می‌شوند؛
  هدر بین حالت تیره و کاغذی عوض می‌شود و ریل شمارهٔ بخش فعال را نشان می‌دهد.
- **میکرواینترکشن:** کشیده شدن زیرخط لینک‌ها و پر شدن دکمه. بدون افکت اضافی.
- **کارایی:** فقط `transform` و `opacity` تغییر می‌کنند؛ یک `IntersectionObserver`
  و یک اسکرول‌لیسنر `passive` کافی است. هیچ کتابخانه‌ای اضافه نشده.
- **دسترس‌پذیری:** کلاس `js` فقط وقتی اضافه می‌شود که `IntersectionObserver`
  موجود باشد و کاربر `prefers-reduced-motion: reduce` را انتخاب نکرده باشد؛
  بدون جاوااسکریپت یا با کاهش حرکت، همهٔ محتوا از ابتدا مرئی است. در چاپ هیچ
  عنصری پنهان نمی‌ماند.

## ۸) محدودیت‌های شناخته‌شده (بدون پرده‌پوشی)

1. **دسترسی از ایران آزمایش نشده است** (بخش ۲).
2. **رابط پنل مدیریت** کتابخانهٔ Decap است؛ برچسب‌ها فارسی و صفحه راست‌به‌چپ شده،
   اما چند جزء رابط (مثل صفحهٔ فهرست) در حالت راست‌به‌چپ چیدمان کاملاً بومی ندارد
   و ممکن است فضای خالی یا هم‌پوشانی جزئی داشته باشد. عملکرد ویرایش و ذخیره
   تحت تأثیر نیست.
3. **توکن GitHub** را Decap در حافظهٔ محلی مرورگر (`localStorage`) نگه می‌دارد؛
   این رفتار خود کتابخانه است. توکن فقط به مخزن همین سایت دسترسی دارد، از
   `Settings → Applications` قابل لغو است و پیشنهاد می‌شود بعد از ویرایش، از پنل
   خارج شوید. هیچ کلید محرمانه‌ای (client secret) در مرورگر قرار نمی‌گیرد.
4. **پیش‌نمایش محتوا** در پنل، ستون پیش‌نمایش ساختاری Decap است (فیلدها و مقادیر)،
   نه رندر دقیق صفحه. دکمهٔ «مشاهدهٔ زنده» سایت منتشرشده را باز می‌کند. پیش‌نمایش
   واقعی صفحه، به انتشار و build نیاز دارد.
5. **شمارهٔ تلفن** با اجازهٔ مالک سایت نمایش داده می‌شود. برای برداشتن آن،
   `phone_visible` را در `content/contact.yaml` خاموش کنید. توجه: مخزن و تاریخچهٔ
   گیت عمومی است، پس شماره‌ای که یک‌بار منتشر شود تا همیشه در تاریخچه می‌ماند.
6. **نمونه‌کارها** خالی است و بخش آن پنهان می‌شود؛ هیچ پروژهٔ ساختگی ساخته نشده.
7. فونت‌ها بدون تغییر (فقط کپی) استفاده شده‌اند تا شرط نام‌محفوظ OFL نقض نشود.
   در سایت فقط دو فایل `woff2` (حدود ۲۴۰ کیلوبایت) ارسال می‌شود؛ نسخهٔ TTF
   استعداد در `scripts/fonts/` فقط برای ساخت تصویر Open Graph است و به خروجی
   سایت ارسال نمی‌شود.
8. تصویر Open Graph در زمان build با `@resvg/resvg-js` ساخته می‌شود؛ روی ماشین
   build به نسخهٔ از پیش کامپایل‌شدهٔ آن نیاز است (در Cloudflare Pages تست‌نشده اما
   استاندارد است؛ اگر مشکل ایجاد کرد، `og.png` موجود در `dist` ثابت می‌ماند).

## ۹) چه چیزهایی واقعاً آزمایش شد

- `npm run build` بدون خطا؛ ۴ صفحه ساخته می‌شود.
- `npm test`: ۲۷ آزمون (محتوا، متادیتا، نبود منبع بیرونی، شمارهٔ تلفن و
  نمونه‌کارها، نبود کلید محرمانه در خروجی، پرتره و `srcset`، جملهٔ کلیدی،
  و وجود قواعد کاهش حرکت).
- رندر صفحه در Chromium (۱۴۴۰ و ۳۹۰ پیکسل): بدون خطای کنسول، بدون منبع شکسته.
- رزومهٔ چاپی با قواعد `@page A4` و پنهان‌شدن عناصر تزئینی در چاپ.
- پنل مدیریت: بارگذاری با ترجمهٔ فارسی، ورود با backend محلی، نمایش و خواندن
  تمام فایل‌های محتوا با نگاشت درست فیلدها.
- توابع OAuth با `wrangler pages dev`: تغییر مسیر ۳۰۲ به GitHub با `state` تصادفی
  و کوکی HttpOnly؛ رد درخواست با `state` نامعتبر (۴۰۰)؛ رد ارائه‌دهندهٔ غیرمجاز (۴۰۰)؛
  مسیر تبادل توکن سمت سرور (پاسخ تمیز در خطای اعتبارنامه).
- سربرگ‌های امنیتی `_headers` روی Cloudflare.

آزمایش‌نشده (صادقانه): ورود واقعی با حساب GitHub و کامیت از پنل به مخزن،
زیرا به اپلیکیشن OAuth و کلیدهای واقعی نیاز دارد؛ و دسترسی از داخل ایران.
